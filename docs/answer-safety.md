# Answer and citation safety

The backend citation validator accepts a generated JSON answer and the retrieved passages that were supplied to the model. Each citation contains a zero-based passage index and an exact, nonblank quote. A valid result identifies the source section and the quote's character offset. If the response is malformed, an answer is blank or uncited, an index is invalid, or any quote is absent, the entire answer is rejected.

This is only one safeguard. Matching a quote does not prove that the answer's claims are supported, or that the passages are within the reader's current boundary. The caller must retrieve only eligible text, verify the boundary again after generation, withhold results if it changed, and handle insufficient evidence. Do not stream unvalidated output to the reader. The local answer API and single-question interface use the validator.

The backend book-answer workflow now combines completed-text keyword retrieval, a model request, and citation validation. It returns a fixed refusal when there is no matching passage or the model reports insufficient evidence. It checks the eligible-text snapshot and watches for database changes before sending text and after generation; any database write causes a conservative retry, including writes unrelated to that book. There remains a small race between the final pre-send check and the network request, and changes during an already-started request cannot retract text already sent. The local answer API uses the selected account, requires a same-origin action and confirmation, and returns no tokens. It supports one question at a time and has only been tested with simulated OpenAI responses. Successful questions and validated answers are saved locally. Follow-up requests can send up to four recent active turns, limited to 4,000 characters total, as context. An oversized recent turn and any older turns are omitted. The model is instructed to treat those turns as context, not evidence, because previous answers may contain unsupported claims. When the current question matches no passages, retrieval falls back to the latest included question, still using eligible text only. Citation matching and model instructions reduce spoiler risk but cannot guarantee that generated claims are supported or spoiler-free.

The endpoint is `POST /api/books/{book_id}/answer` with `question`, `model`, and `confirm: true`. A successful response contains `answer` and `citations`; recognized usage-limit errors contain a machine-readable code. Responses are not streamed to the browser. The current model must be chosen from the account’s available models. A confirmed same-origin `POST /api/chatgpt/models` request retrieves the selected account’s visible models without exposing its tokens; the library picker can load and select those models. The selection is connected to the single-question interface. Any local database write during lookup causes a conservative retry.

The question interface warns that the question, eligible passages, and recent conversation turns may be sent to OpenAI and that model output may contain spoilers. It clears answers and cancels pending requests when the progress control changes, the model changes, or the window loses focus. The displayed answer clears on reload or when asking again. The library can display saved conversation history; it closes and clears the displayed history on window blur or progress changes. Moving progress backward or confirming chapters again hides the old conversation; hidden turns remain in the database until the book is deleted. A transaction makes the final boundary check and save atomic with progress changes.

The experimental `POST /api/books/{book_id}/recap` endpoint accepts `chapter` (one-based), `model`, and `confirm: true`. The optional `mode` is `chapter` (default) or `through`; the latter includes any confirmed front matter and chapters from the beginning through the selected chapter. The selected chapter must be before the current chapter. The endpoint checks progress and chapter-map changes before and after generation, validates citations, and does not save the recap. It rejects selected text over 24,000 characters until multi-stage processing is implemented. The library offers a single-chapter recap control (cumulative recaps are API-only) and tells the reader that the selected chapter is sent to OpenAI. The control clears recaps on progress or model changes and window blur. Recaps are tested with simulated OpenAI responses; citation matching cannot guarantee factual support or prevent model-generated spoilers.
